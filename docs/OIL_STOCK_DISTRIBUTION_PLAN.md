# แผนงานระบบกระจายสต็อกน้ำมันเครื่อง

อัปเดต: 2026-09-13
สถานะ: เริ่มพัฒนา Phase 1

## เป้าหมาย

ต่อยอด benzPOS ให้รองรับสต็อกน้ำมันเครื่องแบบหลายจุดขาย โดยมี **สต็อกกลาง** แยกจาก **สต็อกขายของบ่อถ่ายและแต่ละปั๊ม** แม้สต็อกกลางจะตั้งอยู่บริเวณบ่อถ่ายและพนักงานบ่อถ่ายเป็นผู้จัดของ/นำส่งก็ตาม

หลักสำคัญคือของทุกชิ้นต้องติดตามได้ตั้งแต่สต็อกกลาง -> จอง -> จัดของ -> ออกส่ง -> ปลายทางรับ -> เข้า stock จุดขาย -> ขายผ่าน POS

## โครงธุรกิจ

- สต็อกกลางเป็นคลังกลาง ไม่ใช่จุดขาย
- บ่อถ่ายเป็นจุดขายหนึ่งจุดและมี stock ของตัวเอง
- ปั๊มแต่ละแห่งมี stock ของตัวเอง
- ทุกจุดขายรวมถึงบ่อถ่ายต้องสร้างคำขอเติมสินค้า (Restock Request) จากสต็อกกลาง
- พนักงานบ่อถ่ายเป็นผู้ดูแลการจัดและส่งสินค้าจากสต็อกกลาง
- ปลายทางต้องยืนยันรับสินค้า เพื่อไม่ให้ผู้ส่งเป็นผู้ปิดธุรกรรมเพียงคนเดียว
- ลักษณะการเบิกเป็นครั้งคราว แต่แต่ละครั้งเป็นล็อตใหญ่ จึงไม่ทำ Delivery Run รายวัน

## Workflow หลัก

1. จุดขายสร้างใบเบิกแบบ Draft และใส่หลาย SKU ได้
2. ส่งคำขอ
3. ระบบ Match กับสต็อกกลางและ Reserve ได้เท่าที่มี
4. ถ้ามีไม่ครบ ให้ส่วนที่ขาดเป็น Backorder โดยไม่บล็อกสินค้าที่พร้อม
5. พนักงานบ่อถ่ายเห็นคิวใบเบิกของทุกสาขา
6. เริ่มจัดของ (Picking)
7. ออกส่ง โดยระบุจำนวนส่งจริงต่อ SKU
8. ตัดสต็อกกลางเมื่อของออกจากคลัง และสร้าง Shipment
9. ปลายทางยืนยันจำนวนรับจริง
10. เพิ่ม stock จุดขายตามจำนวนรับจริง
11. ถ้ารับไม่ครบจำนวนส่ง ให้ขึ้น Discrepancy เพื่อให้ตรวจสอบ
12. ถ้ายังมีจำนวนค้างเบิก ให้ใบเบิกอยู่สถานะ Partial/Backorder และสามารถ Reserve/ส่งรอบถัดไปได้
13. เมื่อรับครบตามที่ขอแล้วจึงปิดเป็น Received

## สถานะที่ต้องรองรับ

### Restock Request
- DRAFT
- SUBMITTED
- PICKING
- IN_TRANSIT
- PARTIAL
- RECEIVED
- CANCELLED

### Shipment
- IN_TRANSIT
- RECEIVED
- DISCREPANCY

## ตัวเลขต่อรายการ

แต่ละ SKU ในใบเบิกต้องเก็บอย่างน้อย:
- requestedQty: จำนวนที่ขอ
- reservedQty: จำนวนที่จองและยังอยู่ในคลัง
- shippedQty: จำนวนที่ออกจากคลังแล้วทั้งหมด
- receivedQty: จำนวนที่ปลายทางยืนยันรับแล้วทั้งหมด
- backorderQty = requestedQty - receivedQty - reservedQty - ปริมาณที่กำลังส่ง (คำนวณตามสถานะ shipment)

## สต็อกกลาง

สต็อกกลางต้องแสดง:
- onHand: ของจริงที่ยังอยู่ในคลัง
- reserved: ถูกจองให้ใบเบิก แต่ยังไม่ออกจากคลัง
- available: onHand - reserved
- reorderLevel: จุดเตือนของสต็อกกลาง

สต็อกกลางต้องแยกจาก IngredientStock ของสาขา เพื่อไม่ให้ยอดขายของบ่อถ่ายไปตัดคลังกลาง

## สิทธิ์

ช่วง Phase 1:
- manager ของแต่ละสาขา: สร้าง/ดูใบเบิกของสาขาตัวเอง และยืนยันรับ
- admin: ดูทุกใบ ตั้งค่าสต็อกกลาง และจัดการได้ทุกขั้น
- manager ของสาขาที่ถูกกำหนดเป็นผู้ดูแลคลังกลาง (บ่อถ่าย): ดูคิวทุกสาขา, Reserve, Picking และ Dispatch

ภายหลังอาจเพิ่ม role เฉพาะ warehouse_staff หากจำเป็น

## Audit / ป้องกันความผิดพลาด

ทุกเหตุการณ์สำคัญต้องมีผู้กระทำและเวลา:
- REQUEST_CREATED
- REQUEST_SUBMITTED
- STOCK_RESERVED
- PICKING_STARTED
- SHIPMENT_DISPATCHED
- SHIPMENT_RECEIVED
- RECEIPT_DISCREPANCY
- REQUEST_COMPLETED
- REQUEST_CANCELLED
- WAREHOUSE_STOCK_ADJUSTED

การรับของต้องทำโดยผู้ใช้ฝั่งปลายทาง ไม่ให้ผู้ส่งกดรับแทน ยกเว้น admin พร้อมบันทึก audit

## หลักที่ห้ามเปลี่ยนระหว่างพัฒนา

1. สต็อกกลางกับ stock บ่อถ่ายต้องเป็นคนละยอดเสมอ
2. Reserve ไม่เท่ากับตัด stock; ตัดจากคลังเมื่อ Dispatch เท่านั้น
3. เพิ่ม stock ปลายทางเมื่อผู้รับยืนยันรับเท่านั้น
4. Sale success และ stock transfer success ต้องไม่ผูกกันจนทำให้ POS ขายไม่ได้
5. ทุก mutation ที่เกี่ยวกับจำนวน stock ต้องทำใน transaction และมี movement/audit
6. รองรับส่งบางส่วนตั้งแต่โครงสร้างฐานข้อมูล ไม่ทำเป็น workaround ภายหลัง
