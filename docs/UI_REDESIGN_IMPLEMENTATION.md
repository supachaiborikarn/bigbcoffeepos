# UI และการแยกสาขา — บันทึกการพัฒนา

ปรับปรุง 7 กันยายน 2026

## สถานะ

เผยแพร่ UI และ API รุ่นนี้ตามคำสั่งผู้ใช้แล้วเมื่อ 7 กันยายน 2026 ที่ https://bigbcoffeepos-web.vercel.app โดยเชื่อม https://bigbcoffeepos-api.vercel.app/api และเพิ่มบ่อถ่ายน้ำมันพงษ์อนันต์เป็นรหัส **132** ตามคำสั่งก่อนหน้า

ชุดเผยแพร่แยกการเปลี่ยน POSPOS ที่ค้างอยู่จากงานอื่นออก โดยเก็บงานเหล่านั้นใน workspace ตามเดิม มีสำเนา source ที่เผยแพร่และรหัสรุ่นเดิมสำหรับย้อนกลับใน `output/releases/benzpos-ui-2026-09-07.tar.gz` และ `output/releases/2026-09-07-release.json`

ตรวจหลังบ้านบน Vercel ก่อนและหลังสลับโดเมนผ่าน 13 กรณี ครอบคลุมข้อมูลบัญชี สาขา เมนู สต็อก สมาชิก สูตร หน่วยสินค้า การตั้งค่าร้าน กะ และการปฏิเสธข้อมูลข้ามสาขา/งานส่วนกลาง โดยใช้คำขออ่านเท่านั้น ไม่มีการสร้างบิลหรือปรับยอดขายจริง และเปิดหน้าขายจริงในเบราว์เซอร์ยืนยันว่าแสดง UI ใหม่พร้อมข้อมูลร้านได้

## ผลที่ใช้งานได้ในโค้ดรุ่นนี้

- กาแฟใช้สีครีมกับเขียวเข้ม บ่อถ่ายน้ำมันใช้เทากราไฟต์กับส้ม มีโหมดสว่าง/มืด เมนูพับได้ และเมนูเปิดปิดบนมือถือ
- หน้าขายแสดงประเภทกิจการ สาขาที่กำลังใช้ หมวดสินค้า ราคา ค้นหา และรายการในบิล โดยใช้รูปสินค้าจริงเมื่อมีรูป หากไม่มีจะใช้ภาพประกอบที่ตรงประเภทพร้อมป้ายกำกับ หรือภาพสัญลักษณ์ในหมวดอื่น
- คอมพิวเตอร์แสดงตะกร้าคู่รายการสินค้า ส่วนแท็บเล็ต/มือถือเปิดตะกร้าเป็นแผงเต็มจอ
- กาแฟใช้ตัวเลือกเดิมเรื่องชนิดเครื่องดื่ม แก้ว ความหวาน และส่วนเพิ่ม บ่อถ่ายบันทึกรายละเอียดรถ/งานบริการลงหมายเหตุรายการแรกและใบเสร็จ
- หน้าสต็อกผู้จัดการค้นหา กรองของถึงจุดสั่งซื้อ และแก้ยอดคงเหลือ/จุดสั่งซื้อของสาขาตัวเองได้ โดยรายการขายส่วนกลางให้ admin แก้ไข
- หน้าสมาชิกแสดงรายชื่อ แต้ม และยอดซื้อของสาขา สมาชิกเดิมที่ไม่มีสาขาชัดเจนอยู่ในรายการรอจัดสาขาที่ admin เปิดดูและผูกสาขาเองได้
- บิลพักเก็บสินค้า สมาชิก แต้ม ส่วนลด คูปอง และหมายเหตุใน sessionStorage แยกผู้ใช้/สาขา จึงกลับมาใช้ต่อหลังรีเฟรชหรือสลับสาขาในแท็บเดิมได้
- กะและตะกร้าเปลี่ยนตามพื้นที่ทำงาน คิวออฟไลน์แสดงและส่งเฉพาะบิลของผู้ใช้และสาขาปัจจุบัน พร้อมเก็บบิลของพื้นที่อื่นไว้
- เงินสดคำนวณเงินทอน ส่วน QR/บัตร/Wallet มีการยืนยันโดยพนักงานและเลขอ้างอิง ช่องทางรับเงินใช้รายการที่เปิดไว้ในการตั้งค่าสาขา
- เปิดลิงก์หน้าสต็อก/สมาชิกโดยตรงได้หลังโหลดสิทธิ์ครบ ไม่เด้งกลับหน้าขายระหว่างกู้ session

## ขอบเขตสิทธิ์

ใช้ `User.branchId` และ `User.role` เดิม ผู้จัดการ 7 คนคงสาขาที่ผูกไว้ ไม่มีการเดาการมอบหมายจากชื่อสถานที่ บัญชีไม่มีสาขาที่เปิดใช้งานหยุดที่หน้ารอผูกสาขา ยกเว้น admin ซึ่งคงสิทธิ์ส่วนกลางตามระบบเดิม

เซิร์ฟเวอร์ตรวจสถานะบัญชีและสาขาล่าสุดทุกคำขอ ป้องกันการใช้ token เก่าข้ามสิทธิ์หลังย้ายสาขาหรือปิดบัญชี รวมทั้งตรวจสาขาจากรายการที่อ้างถึง เช่น บิล กะ เอกสารสต็อก และคำขอเปรียบเทียบสาขา

สมาชิกใช้สาขาที่ผูกชัดเจนใน metadata ก่อน หากยังไม่มีจะใช้ประวัติซื้อจากสาขาเดียว ผู้มีประวัติหลายสาขาหรือไม่มีประวัติจะรอ admin จัดสาขา การผูกสาขาเก็บแต้ม ข้อมูลนำเข้า และประวัติรายการเดิมไว้ และไม่อนุญาตให้ขั้นตอนนี้ทับสาขาที่ผูกแล้ว

เมนูและสูตรยังใช้ร่วมกันภายในประเภทร้าน ส่วนโปรโมชั่น/คูปองเป็นข้อมูลส่วนกลางที่ admin แก้ได้ การแยกข้อมูลนี้เป็นคนละชุดต่อสาขายังไม่อยู่ในรุ่นที่ลงโค้ดนี้

## สาขาที่เพิ่มจริง

สคริปต์ `apps/api/src/scripts/add-ponganan-oil-branch.ts` เพิ่ม `บ่อถ่ายน้ำมัน พงษ์อนันต์` ชนิด `oil_service` ได้รหัส 132 และการตรวจซ้ำคืน `already_exists` รหัสเดิม

ไม่มีการเพิ่มพนักงาน ย้ายผู้ใช้ เติมสต็อก หรือตั้งบัญชีรับเงินให้สาขาใหม่โดยคาดเดา โค้ดไม่ได้ยึดว่ารหัสของสาขาใหม่นี้ต้องเป็น 5 หรือ 132

การทดสอบเบราว์เซอร์ใช้แอปที่ build จริงและดักคำขอ API ด้วยข้อมูลจำลอง จึงไม่ได้สร้างบิลหรือแก้สต็อกจริง ส่วนชุด integration ใช้ PostgreSQL ชั่วคราวในหน่วยความจำที่สร้างโครงจาก Prisma และตารางเสริมของกะ โดยปิดฐานทดสอบเมื่อจบ

คำสั่งตรวจจากราก repository:

```sh
npm run build --workspace apps/web
npm run build --workspace apps/api
npm run pos:smoke --workspace apps/api
npm run production-hardening:check --workspace apps/api
node --import tsx apps/api/src/scripts/branch-access-check.ts
node apps/web/scripts/offline-scope-check.mjs
git diff --check
```

ชุด `apps/api/src/scripts/checkout-integration-check.ts` ต้องใช้ฐานทดสอบแยกที่มี schema ครบเท่านั้น ห้ามชี้ชุดนี้ไปยังข้อมูลร้านจริง

ไฟล์สำหรับ Playwright CLI `run-code` อยู่ที่ `apps/web/scripts/studio-browser-check.js` และ `apps/web/scripts/studio-backoffice-check.js` โดยใช้ Vite preview ที่ `http://127.0.0.1:5176` และข้อมูลจำลองในไฟล์ สร้างโฟลเดอร์ `output/playwright` ก่อนรัน ภาพที่บันทึกจึงเป็นภาพแอปจริงบนข้อมูลทดสอบ

## สิ่งที่ยังต้องทำจากแผนใหญ่

- เผยแพร่ web และ API พร้อมกันแล้ว รุ่นถัดไปต้องรักษาความเข้ากันได้ของ `/auth/me` และการตรวจสาขา
- กำหนดพนักงาน สต็อกตั้งต้น และอุปกรณ์/บัญชีรับเงินของสาขาใหม่จากข้อมูลที่ผู้ใช้ยืนยัน
- ยังไม่มีแบ่งชำระหรือยืนยันรับเงินจากผู้ให้บริการอัตโนมัติ และยังไม่ได้ทดสอบรับเงินจริง เครื่องพิมพ์จริง เครื่องอ่านบัตร หรืออุปกรณ์หน้าร้าน
- บ่อถ่ายยังไม่มีตารางนัด ช่องบริการ ประวัติรถ และใบงานที่มีสถานะแยก รายละเอียดรถปัจจุบันเป็นหมายเหตุในบิล
- หน้ารายงาน ออเดอร์ คิว และส่วนดูแลระบบใช้ธีมและโครงเมนูใหม่ แต่ยังไม่ได้ออกแบบรายละเอียดทุกหน้าตามแผน
- เมนู/สูตร/โปรโมชั่นแยกอิสระต่อสาขาต้องวางโครงข้อมูลและการย้ายเพิ่มเติม สมาชิกยังใช้เบอร์โทรไม่ซ้ำทั้งระบบตาม schema เดิม
- บิลพักอยู่ใน sessionStorage ของแท็บนั้น และคิวออฟไลน์อยู่ในเครื่องเดิม การเปิดแอปใหม่ขณะไม่มีอินเทอร์เน็ตยังต้องเชื่อมต่อเพื่อยืนยันบัญชี

## ผลกระทบและทางย้อนกลับ

โค้ดนี้แตะเส้นทางสิทธิ์และการขายจึงต้องเผยแพร่เป็นชุดเดียวกัน การย้อน UI ทำได้จาก diff โดยคงการตรวจสิทธิ์ที่แก้แล้วไว้ ไม่มี migration โครงข้อมูลจริงในงานนี้ สาขา 132 เป็นข้อมูลเพิ่มตามคำสั่งผู้ใช้และไม่ควรลบทิ้งเพื่อย้อนหน้าตา

มีงานแก้ค้างจากงานอื่นใน repository จึงเผยแพร่จากชุด source ที่แยกเฉพาะงานนี้ โดยยังไม่ได้ commit รวมไฟล์เหล่านั้น และไม่ได้ย้ายพนักงานหรือแก้บิลเก่า
